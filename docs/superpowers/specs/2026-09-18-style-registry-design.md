# Style registry: one visual-style catalog for characters and videos

Date: 2026-09-18  
Status: approved in chat, pending spec review

## Goal

Today "style" lives in two unrelated places: the director **Skill** in Mongo (`skills`, seeded from `skills/cartoon-explainer-video-director/*.md`, whiteboard-doodle baked into the prompt) and a one-entry code catalog `src/lib/styles.ts` used only for character blueprints. This spec makes **one style registry** that both pipelines read, adds a **typography guideline** to every style, ships **eight new styles**, moves image generation to **GPT Image `medium`**, and shows a **generated preview image** for each style in the character and video creation forms. It also folds in two redo-consistency fixes found while debugging frame regeneration: opaque backgrounds and a sibling-frame style reference.

## Decisions already made

- **Style is an independent axis from Skill.** One director Skill + N visual styles. Style text is appended to the Phase A/B system prompt as an explicit override of SKILL.md's "Locked visual world"; SKILL.md itself is not rewritten per style.
- **Definitions live in code** (`src/lib/styles.ts`, typed constants). A new Mongo `styles` collection stores only generated state (preview URL, prompt hash).
- **Previews are generated by a seed script** (`npm run seed:styles`) with GPT Image 1.5 `medium`, persisted to Vercel Blob, run before deploy. No lazy generation in the request path.
- New styles: flat-vector, paper-cutout, chalkboard, watercolor, clay, pixel, ink-manga, realistic (plus existing doodle = 9).
- Image model stays `openai/gpt-image-1.5` (Higgsfield has no 2.x yet). Quality moves from `low` to `medium` for stills and frames; blueprints already use `medium`.
- Existing `Character.styleId` and the `"doodle"` id are kept for compatibility. Videos without `styleId` are treated as `doodle`.

## Out of scope

- Switching image models (gpt-image-1.5 is deprecated by OpenAI on 2026-12-01; migration is a separate task).
- Per-style SKILL.md variants or per-style director references.
- Letting one video mix styles, or restyling an existing character/video.
- Admin UI for styles; the seed script is the only management path.

## Data model

### `src/lib/styles.ts` (rewritten)

```ts
export type StyleId =
  | "doodle" | "flat-vector" | "paper-cutout" | "chalkboard"
  | "watercolor" | "clay" | "pixel" | "ink-manga" | "realistic";

export type Style = {
  id: StyleId;
  name: string;          // English name
  nameZh: string;        // picker label
  description: string;   // one line, picker sub-label (zh)
  canvas: string;        // surface: "clean solid white canvas", "dark green chalkboard", ...
  canvasColor: string;   // hex; picker card background and alpha-flatten colour
  look: string;          // line / fill / shading technique
  palette: string;       // colour guidance in plain words (no hex: SKILL.md rule)
  typography: string;    // on-canvas text: hand, weight, case, label/tag shape, placement
  motion: string;        // how things move in this style (Phase B)
  negatives: string;     // what to forbid
  previewPrompt: string; // fixed preview scene, identical across styles
};

export const STYLE_IDS: StyleId[];
export const STYLES: Record<StyleId, Style>;
export const DEFAULT_STYLE_ID: StyleId = "doodle";
export function isStyleId(value: string | undefined): value is StyleId;
```

The `doodle` entry is a faithful condensation of SKILL.md's current "Locked visual world" (canvas, marker outlines, palette words, `short handwritten all-caps marker labels`), so doodle output does not change in intent. The preview scene is shared: a friendly character pointing at a light bulb labelled `IDEA`, with one arrow — same composition per style so the nine previews compare directly and each shows how the style renders text.

`stylesCollection<StyleDoc>()` in `src/lib/collections.ts`.

### `Project` (video) — `src/types/project.ts`

- `styleId?: StyleId` — set on create; readers use `project.styleId ?? DEFAULT_STYLE_ID`.
- `PublicVideo.styleId: StyleId` (resolved, never undefined).

### `PublicStyle` — `src/lib/serialize.ts`

`{ id, name, nameZh, description, canvasColor, previewUrl? }`. `listPublicStyles()` (server-only, `src/lib/styles/list.ts`) merges `STYLES` with the `styles` docs in `STYLE_IDS` order.

## Prompt injection

New module `src/lib/styles/prompts.ts` (pure functions, unit tested):

- `styleBlockForDirector(style)` → markdown:

  ```
  ## Visual style (overrides the "Locked visual world" section above)
  Canvas: …  Look: …  Palette: …  Typography: …  Motion: …  Never: …
  Keep every other rule (hooks, pacing, clip structure, cast lock) unchanged.
  ```

  `skillPromptForPhaseA(skill, style)` / `skillPromptForPhaseB(skill, style)` append it after the references. `runPhaseA` / `runPhaseB` gain a `style` input; callers resolve it from the video.

- `styleLinesForFrame(style)` → replaces the two hard-coded lines at the top of `buildFramePrompt` ("Single storyboard still for a whiteboard-doodle…", "Clean solid white canvas, bold irregular…") with: `Single storyboard still for a ${style.name} explainer video.`, `Canvas: ${canvas}. Look: ${look}. Never: ${negatives}.` The existing spelling line becomes `Lettering: ${typography}. Any on-canvas text must be spelled exactly as written in the scene description.` `stillPrompt` in `pipeline.ts` uses the same helper.

- `styleLinesForBlueprint(style)` → replaces `STYLES[id].promptFragment` in `buildBlueprintPrompt`; `SHEET_LAYOUT`'s "solid white background" and "blank white space" become `${style.canvas}` / "blank margin", so a chalkboard character sheet sits on a chalkboard.

Phase A's `visualWorld` / `palette` / `characterLock` output fields are unchanged; the director fills them per style.

## Generation quality and redo consistency

- **Medium**: `scripts/seed-skills.ts` `imageQuality: "medium"`; both `|| "low"` fallbacks in `pipeline.ts` become `|| "medium"`; re-run `npm run seed:skills`. `TYPICAL_COGS_PER_CREDIT_USD` in `src/lib/billing/unit-economics.ts` 0.20 → 0.225 (measured: +$0.075 per clip; margins drop 1–2.5 pt; prices unchanged).
- **Opaque background**: `submitImage()` sends `background: "opaque"` for gpt-image models. Because Higgsfield silently drops unknown fields, the plan includes a probe with the estimate endpoint; independent of the result, `applyJobStatus` flattens any PNG with alpha onto `style.canvasColor` (via `persistMedia`'s `transform`, `sharp.flatten`) for `still` and `frame` jobs. `flattenToCanvas(buffer, hex)` lives in `src/lib/higgsfield/flatten.ts`, unit tested.
- **Sibling reference**: `regenerateFrames()` looks up the other completed frame of the same clip (`start`↔`end`) and passes its URL as `styleRefUrl` to `submitOneFrame`. Reference order: `[revision.annotatedUrl, styleRefUrl, ...lockRefs]`. `buildFramePrompt(project, clip, position, { revision, styleRefUrl })` adds: `A sibling frame from the same clip is attached: match its line weight, character proportions, colouring and lettering exactly.` Initial batch generation passes no sibling. The frame-prompt signature changes to an options object; `initialFrames`, `regenerateFrameAction`, `updateClipStoryboardAction` adapt.

## Preview generation

`scripts/seed-style-previews.ts`, `npm run seed:styles [--force] [--only=<id,…>]`:

1. For each `StyleId`: compute `previewHash`. Skip if the doc has the same hash and a `previewUrl`, unless `--force`.
2. `submitImage({ model: "openai/gpt-image-1.5", quality: "medium", aspectRatio: "16:9", prompt })` where prompt = `styleLinesForFrame(style)` + `style.previewPrompt` + `Aspect ratio 16:9.` No references, no webhook (the script polls `fetchHiggsfieldStatus` every 3 s, 5 min timeout).
3. On `completed`: `persistMedia(url, "explainer/styles/<id>")` with the flatten transform; upsert the `styles` doc.
4. One failure logs and continues; exit code 1 if any failed. Cost: 9 × ≈$0.05.

Webhook safety: the script never sets a webhook, so no stray callbacks; even if one arrived, `applyJobStatus` ignores unknown request ids.

## UI

- `src/components/style-picker.tsx` (shared, `"use client"`): `role="radiogroup"` grid (`sm:grid-cols-3`), each card = `aspect-video` preview (`<img>` when `previewUrl`, else a `canvasColor` block with `nameZh`) + `nameZh` + `description`. Selected state mirrors `SkillPicker` (ink background, paper text). Props: `styles: PublicStyle[]`, `value`, `onChange`, `disabled`.
- Video form `new-project-form.tsx`: Step 01 keeps `SkillPicker` and adds a `StylePicker` under it (label 視覺風格). `createVideoAction` reads `styleId`, validates with `isStyleId`, stores it. Server page `projects/[id]/page.tsx` (and `projects/new`) fetch `listPublicStyles()`.
- Character step: `CharacterPicker` receives `styleId`; characters with a different `styleId` render disabled with a 「風格不同」 badge. Changing the style removes now-incompatible ids from the selection.
- Character modal `create-character-modal.tsx`: text chips → `StylePicker`; page fetches `listPublicStyles()`.
- Frames timeline / project header: show the style `nameZh` chip next to the language chip (read-only).

## Error handling

- Missing preview → placeholder card; creation is never blocked on previews.
- Invalid `styleId` in a form → `{ ok: false, error: "請選擇視覺風格" }`.
- Videos created before this change → `doodle` everywhere (serialize, pipeline, director).
- Sibling lookup finds no completed frame → no sibling ref, prompt line omitted.
- Flatten failure → log and persist the original bytes (never fail a completed job on a cosmetic step).

## Success criteria

- One file (`src/lib/styles.ts`) defines every style; no whiteboard literal remains in `frame-prompts.ts`, `pipeline.ts`, or `blueprint-prompt.ts`.
- Each style carries a typography guideline that reaches Phase A, Phase B, frame prompts and the preview.
- Both creation forms show nine style cards with generated previews.
- Stills and frames are generated at `medium`, persisted without alpha, and single-frame redos include the sibling frame as a reference.
